# PHASE 11.2 design — scheduler and suspension

Status: **design only**. PHASE 11.1 provides `async fn`, `await` and `Future`,
but the body runs eagerly: a future is already settled when the caller receives
it, `await` never suspends and there is no pending-future producer. This page
records the design for the real async runtime. It is not implemented.

`DEVELOPMENT.md` §PHASE 11 is the current status; this page is the design
record for the slices that follow.

---

## 1. Goal

Make `async fn` a real cooperative task, not a naming convention:

```oskel
async fn fetchName(id: int): string {
  await sleep(10);
  return "user-" + str(id);
}

async fn main(): void {
  let a = spawn fetchName(1);
  let b = spawn fetchName(2);
  print(await a);  // user-1
  print(await b);  // user-2
}
```

- Calling an `async fn` returns a **pending** `Future`; it does not run the
  body.
- `spawn f(...)` enqueues the call as a task and returns its future.
- `await f` on a pending future suspends the current task, not the process.
  Other ready tasks run until `f` settles, then the awaiter resumes.
- `await f` on a fulfilled future returns its payload immediately; on a
  rejected future it yields the error value (the current error-value model,
  not an exception).
- A single-threaded cooperative scheduler owns the ready queue. There is no
  preemption and no parallelism.
- `main` may be `async`; the CLI drains the scheduler before it exits.

Non-goals for 11.2: OS threads, parallel execution, preemption, async I/O
drivers, cancellation and a work-stealing runtime. Those are later slices.

## 2. Why a state machine and not stackful coroutines

The VM already has explicit frames (`VM::frames_`), so a stackful coroutine
would be possible there. The AOT backend and WASM do not: an Oskel function is
a native/WASM function with a native stack, and neither backend can switch a
C/WASM stack portably (`ucontext` is POSIX-only, Windows needs Fibers, and WASM
has no stack switching without Asyncify/JSPI).

The portable choice is a **compiler-generated state machine**. The compiler
splits an async body at every `await` into resumable segments; the generated
bytecode uses only the opcodes the three engines already implement. The
scheduler and the future protocol are ordinary functions over maps, closures
and arrays, so VM, AOT and WASM share one implementation by construction. No
backend grows a second calling convention.

This is the same trade-off the language already made for `class` and `Future`:
lower the feature to existing primitives rather than add a runtime mechanism
each backend must reimplement.

## 3. Runtime representation

### 3.1 Future map protocol

A future is a map with a private protocol. The compiler treats the `Future`
type as opaque: indexing a `Future`-typed value or assigning one of its members
is a compile error, so ordinary code cannot inspect or mutate the state. A
value whose static type was erased to `any` can still reach the keys; the
runtime tag that closes that hole is 11.2.5.

```text
{
  "$future": true,
  "state":   "pending" | "fulfilled" | "rejected",
  "value":   <payload> | nil,
  "error":   <error> | nil,
  "task":    <closure> | nil,
  "waiters": <array of continuations>
}
```

`state` and `value` keep the PHASE 11.1 shape, so an existing `Future`-typed
value remains readable. `task` is the resumable body; `waiters` are the
continuations to enqueue when the future settles.

A rejected future carries an error value. `await` returns that error value, so
`isError(await f())` keeps working; an unhandled rejection is not a process
abort in 11.2.

### 3.2 Task frame

A task owns the state a suspended body needs:

```text
{
  "future":  <the future it settles>,
  "step":    <closure: frame -> status>,
  "pc":      <resume point>,
  "args":    <array of parameters>,
  "regs":    <array of saved registers>,
  "locals":  <array of cells>,
  "done":    false
}
```

`step` is generated by the compiler. It runs from `pc`, saves `regs`/`locals`
before returning a suspension status, and resumes at `pc` on the next call.
`locals` holds cells, so closures created before an `await` keep sharing the
same bindings after it.

### 3.3 Status values

`step` returns one of:

```text
{ "kind": "done",      "value": <payload> }
{ "kind": "suspended", "future": <awaited future> }
{ "kind": "failed",    "error": <error> }
```

The scheduler reads `kind`; the program never sees it.

## 4. Compiler lowering

The lowering is a compiler pass over the async proto. It runs before the
bytecode reaches the VM, the AOT lowerer or the WASM emitter, so no backend
needs to know that a function was async.

### 4.1 Factory

For `async fn f(a: int): T`, the compiler emits two protos:

1. **factory** — the value bound to `f`. It takes the declared parameters,
   creates the future map and the task frame, stores the body closure, and
   returns the future without calling the body.
2. **body** — the original body, rewritten as a step function. It takes the
   task frame as its only parameter and reads its arguments from `frame.args`.

`await f()` therefore sees a pending future; `spawn f()` only enqueues the
task. Calling `f()` and never awaiting it is a leaked pending task, not an
eager execution. The design keeps the existing rule that an async function is
a first-class value: `let g = f; await g(1)` still works.

### 4.2 Splitting at `await`

The body is split into basic blocks at each `await` expression. Each block gets
an integer resume id. The step function begins with a dispatch on `frame.pc`:

```text
if frame.pc == 0: goto block0
if frame.pc == 1: goto block1
...
```

An `await expr` lowers to:

```text
f = <expr>
status = $awaitProbe(f)          // ready? value or error
if status.ready:
  result = status.value          // continue the block
else:
  spill R0..Rn into frame.regs
  frame.pc = <next block id>
  return { kind: "suspended", future: f }
```

`$awaitProbe` is a compiler-private helper emitted as ordinary bytecode, not a
new opcode and not a public builtin. It reads the future map: a fulfilled
future returns `{ready: true, value: ...}`; a rejected one returns the error as
the payload; a pending one returns `{ready: false}`.

The compiler must spill every register that is live across the await. The
existing register allocator already knows the live range at each instruction;
the pass records that set on the await instruction and emits the spill/restore
pairs. Locals are already cells, so they survive in `frame.locals`; a local
that is captured by a closure is the same cell before and after the await.

### 4.3 Returns

Every `return` in the body becomes:

```text
frame.future.value = <value>
frame.future.state = "fulfilled"
return { kind: "done", value: <value> }
```

A body that falls off the end fulfills with `nil`, as today. A `return` inside
a `defer` or a loop is handled by the same rewrite; the splitter treats the
whole body as one control-flow graph, not as a linear statement list.

### 4.4 Top-level `await`

11.2 allows `await` in the root chunk by wrapping the chunk in a task and
draining the scheduler before the CLI exits. The parser's `asyncDepth_` guard
changes from "inside an `async fn`" to "inside an `async fn` or the root
chunk". The REPL keeps its existing synchronous entry point; a top-level await
there is rejected until the REPL grows a scheduler loop.

## 5. Scheduler

A single ready queue of task frames, FIFO:

```text
spawn(task):
  if task.future.state == "pending" and not task.enqueued:
    ready.push(task)
  return task.future

await(f):
  if f.state != "pending": return f.value or f.error
  current = runningTask
  f.waiters.push(current)
  return suspend()

yield():
  ready.push(runningTask)
  return suspend()

run():
  while ready is not empty:
    task = ready.pop()
    runningTask = task
    status = task.step(task)
    if status.kind == "done": settle(task.future, status.value)
    else if status.kind == "failed": reject(task.future, status.error)
    else: register task as a waiter of status.future
  if runningTask still suspended: deadlock error
```

`settle(future, value)` moves every waiter from `future.waiters` to the ready
queue. `reject` stores the error in `future.error` and wakes the waiters; the
awaiting task receives the error value.

`await` on a pending future that has never been spawned starts it, so the
common `await f()` form does not require `spawn`. `spawn` is the explicit way
to start a task without awaiting it immediately.

## 6. AOT and WASM

No new opcode and no backend-specific suspension mechanism:

- The factory/body split is bytecode, so `lower.cpp` and `wasm.cpp` lower the
  same `CALL`, `RETURN`, `NEWTABLE`, `GETTABLE`, `SETTABLE` and jumps they
  already handle.
- The scheduler and `spawn`/`yield` are ordinary Oskel functions over maps and
  arrays, emitted into the program's prelude. They are not new builtins, so
  `check_builtin_parity` needs no exception.
- `$awaitProbe` is compiler-private and emitted as a normal proto; the AOT
  lowerer treats it like any other function.
- The freestanding, hosted and WASM images carry the same scheduler code. A
  program that never mentions `async` must keep its byte-for-byte image; the
  prelude functions are emitted only when an async proto exists.

The AOT backend's JIT is unaffected: the JIT accepts only integer-only protos
and falls back to the interpreter for everything else. Async bodies fall back
by construction.

## 7. Errors and limits

- `await` outside an async context remains a compile error.
- `await` on a non-`Future` remains a compile error; an unknown static type
  falls back to the runtime state check.
- A task that throws a runtime error rejects its future; the awaiting task
  receives the error value. A task with no waiter and a rejected future is
  reported at the end of `run()` as an unhandled rejection, not silently
  dropped.
- A cycle of pending futures (A awaits B, B awaits A) is a deadlock; `run()`
  raises a runtime error naming the stuck task rather than spinning.
- `async fn init` stays rejected; a constructor is called without `await`.
- `spawn` and `yield` are available only where a scheduler is running. In a
  synchronous chunk they are compile errors or raise a clear runtime error;
  the design chooses a compile error when the enclosing chunk is not async.

## 8. Opcode budget

**No new opcode.** The state machine, the probe and the scheduler use
`NEWTABLE`, `GETTABLE`, `SETTABLE`, `CALL`, `RETURN`, `MOVE`, `LOADK`, the
comparisons and the jumps. The budget stays at 39 active opcodes, so the
retirement ladder in `DEVELOPMENT.md` §3.3 is not touched.

If a later slice needs a scheduler yield point that cannot be a helper call,
the first candidate is a retirement, not a 41st opcode.

## 9. Slices

| Slice | Scope | Exit criterion |
|-------|-------|----------------|
| 11.2.1 | Compiler-enforced `Future` opacity and state transitions; no scheduler yet | Direct indexing/member access on a `Future` is rejected, pending/fulfilled/rejected are distinguishable |
| 11.2.2 | Task frame, factory/body split, `spawn`, `yield`, ready queue | A spawned task runs after the spawner reaches `await`; VM/AOT/WASM order matches |
| 11.2.3 | Split at `await`, spill/restore, suspension | A task suspends at a pending future and resumes after it settles; interleaving order is asserted |
| 11.2.4 | Top-level `await`, unhandled rejection, deadlock diagnostics | Scripts can await at top level; stuck and unhandled cases have tests |
| 11.2.5 | Runtime tag, cancellation, async timers/I/O | Optional; only after 11.2.1-11.2.4 are stable |

11.2.1 is deliberately separate: it fixes the opaque-value contract and gives
the scheduler a real `pending` state without requiring the control-flow
splitter. 11.2.2 can then schedule eager bodies; 11.2.3 adds the suspension
that makes `await` meaningful.

## 11. Risks

- **Register spilling across `await`.** A wrong live set silently corrupts a
  temporary after resume. The splitter must use the existing liveness data,
  and the fixture must await inside an expression with a live temporary
  (`1 + await f() + 2`), not only in statement position.
- **Locals captured by closures.** Cells must be the same object before and
  after suspension. `frame.locals` stores cells, not values.
- **`defer` and `try` across a suspension.** A `defer` that must run when the
  body returns has to run on the final resume, not on a suspension. The
  splitter needs a per-frame defer stack; 11.2.3 covers it before any fixture
  uses `defer` around an `await`.
- **Code size.** Every async body gets a dispatch prologue and a spill/restore
  path. A program with no async must not pay for it; the prelude is emitted
  only when the chunk contains an async proto.
- **WASM control flow.** The splitter emits many blocks and jumps; the WASM
  validator rejects an unbalanced block/loop, so the emitter's label discipline
  needs the same tests as the existing structured-control lowering.

## 12. Seven-point checklist for 11.2.1

- **Lexer:** no new token. `async` and `await` already exist.
- **AST:** no new node. `AwaitExpr`, `FnDeclStmt::isAsync` and the `Future`
  type name already exist; 11.2.1 only adds compiler checks.
- **Parser:** no new rule. The existing `asyncDepth_` guard stays; top-level
  await is 11.2.4.
- **Bytecode:** no new opcode. Future construction is `NEWTABLE`/`SETTABLE`;
  state transitions are `GETTABLE`/`SETTABLE` and comparisons.
- **ASM mapping:** not applicable; no opcode is added.
- **VM:** no new value kind. The existing map operations implement the state;
  the compiler is the layer that makes the type opaque.
- **Compiler:** the `Future` type remains the call-site type; 11.2.1 adds the
  index/member checks that reject direct access to a `Future`-typed value and
  the state transitions. It adds no control-flow rewrite; 11.2.2 adds the
  factory/body split.
- **AOT/WASM:** no backend change. The value stays a map, so `AotValue` and the
  WASM tag set are untouched; the builtin parity gate covers any new helper.
  No suspension is lowered in 11.2.1.
- **Platforms:** Linux, Windows, macOS; VM, freestanding/hosted AOT and WASM.
  The fixtures run on every CTest platform, and the WASM fixture runs where
  Node is present.

Without approval of this checklist, 11.2.1 is not started.
